## 从一个 Python App，到一套可交付的自动化。

Workrun 不是只能画流程图。你可以先创建一个独立运行的本地 Python 项目，用代码完成一件具体的事；也可以在画布上把 Agent、App、MCP 工具与人工判断编排成可重复运行的流程。两种方式共享同一个运行、调试、评测与发布工作台。

## App 不只是节点：先独立完成一件事

无论是数据处理、文件操作、内部系统集成，还是需要人工输入的本地小工具，App 都可以直接从 **Apps** 页面运行。Workrun 负责项目创建、运行记录与运行时交互；Python 代码依然是你自己的代码工程。

## 当一个 App 不够时，再把它编排进 Workflow

工作流配置不应是黑盒。节点从哪里取数据、由谁判断、何时暂停给人处理，以及一次运行使用的模型和工具，都应该可见、可检查。

## 无论从哪里开始，都在同一个工作台演进

| 你要完成的事   | Workrun 如何帮助你                                      |
| -------------- | ------------------------------------------------------- |
| 组合能力       | 独立运行 App，或在画布上连接 Agent、Process、分支、子工作流和人工节点。 |
| 可靠运行       | 节点状态隔离；等待输入时继续，应用中断后恢复；失败后重新运行。      |
| 看清发生了什么 | 逐节点查看模型消息、工具调用、脚本日志和 Trace。        |
| 安心迭代       | 用评估集验证工作流变化，并在发布前设置质量门。          |
