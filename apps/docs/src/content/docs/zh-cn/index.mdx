## 从一句需求，到一套能运行的工作流。

告诉 Workrun 你想完成什么，它会帮你梳理步骤、选择所需能力，并生成可重复运行的工作流。你可以通过对话完善方案、调整流程，也可以随时打开画布编辑细节。已有合适的工作流时，直接让它帮你找到并运行。

## 一个日常例子：查天气，再规划行程

视频从“根据杭州天气给出行程规划”开始：选择开始规划后，在 Human Review 中将 `input` 的“杭州”改为“上海”，再批准并继续。天气查询 Agent 调用工具获取天气，行程规划 Agent 读取查询结果并给出建议；问题回答、人工审核和工具授权都在节点消息中完成。

```text
输入杭州出行需求 → 选择开始规划 → 审核时改为上海 → 授权天气查询 → 获取上海天气 → 生成上海行程建议
```

**亲自运行这个例子：** <a href="/examples/workflows/weather-trip-planning.zip" download>下载示例 Workflow（ZIP）</a>，包内包含工作流和天气查询 App 源码。

1. 在 Workrun 的 Workflow 列表选择 **导入 Workflow**，打开下载的 ZIP 文件，无需解压。
2. 按提示绑定当前设备上的模型配置，确认导入，并安装天气查询 App 的依赖。也可以稍后通过 **配置导入依赖** 补齐模型配置。
3. 打开导入的工作流，输入“根据杭州天气给出行程规划”并运行，跟随问题、人工审核和工具授权卡片体验视频中的流程。

详细操作见[导入与导出工作流](/zh-cn/guides/build-a-workflow/#分享或删除已保存的-workflow)。

**审核也可以修改实际内容。** 用户最初输入的是“根据杭州天气给出行程规划”。本例将审核节点的内容键设为 `input`，并开启“允许编辑”；审核时把“杭州”改成“上海”，再批准并继续。修改会写回同一个状态键，因此后续工具查询的是上海天气，行程规划也以修改后的需求为准。你可以在工具授权卡片中核对调用参数 `city: "上海"`，确认这次编辑已影响下游执行。

| 步骤     | 谁负责                                | 交付什么                                           |
| -------- | ------------------------------------- | -------------------------------------------------- |
| 确认需求 | 你通过问题和审核卡片选择、修改或批准  | 本次出行需求；选择暂不规划或拒绝审核则结束运行     |
| 查询天气 | 天气查询 Agent 调用已配置的天气工具   | 天气信息 `weather_info`，向行程规划 Agent 开放读取 |
| 规划行程 | 行程规划 Agent 读取需求与上游天气信息 | 基于查询结果的行程建议，不自行编造天气             |

视频展示的是编排与交互方式，实际天气取决于所接工具的数据来源与查询时间。只有当前天气时，行程建议应作为参考，不能当作未来天气预报。了解[人工交互的配置](/zh-cn/guides/human-in-the-loop/)和[节点间的状态传递](/zh-cn/concepts/workflows-and-state/)。

## 无论从哪里开始，都在同一个工作台演进

| 你要完成的事   | Workrun 如何帮助你                                                      |
| -------------- | ----------------------------------------------------------------------- |
| 组合能力       | 独立运行 App，或在画布上连接 Agent、Process、分支、子工作流和人工节点。 |
| 可靠运行       | 节点状态隔离；等待输入时继续，应用中断后恢复；失败后重新运行。          |
| 看清发生了什么 | 逐节点查看模型消息、工具调用、脚本日志和 Trace。                        |
| 安心迭代       | 用评估集验证工作流变化，并在发布前设置质量门。                          |
