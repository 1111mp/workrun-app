title: 为 App 和工作流配置定时运行
description: 从定时任务入口通过对话创建和管理一次性或周期性任务，按指定时区运行本地 App 或工作流。
---

从侧边栏的 **定时任务** 入口，可以通过对话安排 App 或工作流在指定时间运行，无需每次手动启动。支持一次性任务和周期性任务。任务保存在本地；下次打开 Workrun 后会继续调度。

> 定时任务仅在 Workrun 桌面应用保持打开时运行，并不是云端后台服务。对时间要求严格的自动化请保持 Workrun 运行。

## 从定时任务入口开始

![定时任务入口：从侧边栏进入，通过对话输入需求，或切换到任务列表查看已安排的任务。](/media/schedules/03-scheduled-tasks-entry.png)

### 通过对话安排任务

1. 点击侧边栏的 **定时任务**，选择一个已配置的模型。
2. 描述要运行的 App 或工作流、执行时间和所需输入。例如：“每周五下午五点运行项目周报工作流，时区为 Asia/Shanghai”，或“2026 年 11 月 10 日上午九点运行数据同步 App，仅执行一次”。请使用实际需要的未来日期。
3. 如果助手询问执行目标、时间或输入，补充信息后继续。
4. 检查确认卡片中的目标、运行输入、时区和执行时间。周期性任务还会预览后续触发时间。
5. 点击 **创建任务**，看到 **已保存** 后，任务才正式生效。需要调整时可继续对话，核对新的提议后再确认。

助手的回复和待确认提议不等于已经保存的任务。停止回复也不会撤销此前已确认保存的配置。

![通过对话为 User Info App 创建每天上午十点运行的任务，确认卡片显示已保存，下方显示启用中的任务。](/media/schedules/04-create-schedule-conversation.png)

图中以“每天上午十点整运行 User Info 的 App”为例，确认后任务按 `Asia/Shanghai` 时区每天 10:00 执行。已保存的任务卡片会显示下一次执行时间，可点击 **查看任务** 检查详情。

### 查看与管理已安排的任务

切换到 **任务列表**，可搜索任务，并按 **全部任务**、**启用中**、**已暂停** 或 **需处理** 筛选。点击任务查看执行安排、运行输入和最近运行；点击 **查看结果** 检查对应运行。

你也可以继续对话，例如“把项目周报改到每周五下午六点”“暂停数据同步任务”或“查看最近的执行结果”。通过对话修改、暂停、恢复或删除任务时，需要核对确认卡片并确认操作。任务详情也提供编辑、暂停、恢复与删除操作。

删除任务后不再触发后续运行，已有运行记录仍会保留；暂停任务不会停止已经开始的运行。可以通过 **对话记录** 返回之前的安排过程，或再次点击侧边栏 **定时任务** 开始新对话。

## 一次性任务与周期性任务

- **一次性任务**：在指定日期和时间执行一次。确认前检查完整日期、时间与时区；任务结束后可在列表中查看其状态与运行记录。
- **周期性任务**：按频率或 Cron 规则重复执行，并显示下一次运行时间。需要暂停后续运行时可暂停任务。

一次性任务不需要编写 Cron。下面的 App 和工作流配置入口用于设置周期性任务。

## 从 App 或工作流配置周期性任务

### App 定时任务

1. 进入 **Apps**，选择要自动运行的 App。
2. 在 **Schedules** 中点击 **New schedule**。
3. 填写易识别的名称，选择预设频率或 **Custom Cron**，然后选择时区。
4. 检查预览，点击 **Save schedule**。

### 工作流定时任务

1. 打开工作流编辑器，在设置中找到 **Automation**。
2. 点击 **New schedule**。
3. 填写工作流输入。保存前必须填写所有必填输入。
4. 选择频率、时间（或自定义 Cron）与时区，检查后续触发时间，然后保存。

任务列表会在所选时区显示每条任务是否启用以及下一次运行时间。使用开关暂停或恢复，点击铅笔编辑，点击删除按钮移除。删除后无法恢复。

## 选择频率或编写 Cron

**Every day**、**Every weekday** 和 **Every week** 会自动生成表达式。需要其他规则时选择 **Custom Cron**。

周期性任务仅接受由五个、以空格分隔的字段组成的 Cron：

| 位置 | 字段 | 示例                 |
| ---- | ---- | -------------------- |
| 1    | 分钟 | `0`、`*/15`、`5,35`  |
| 2    | 小时 | `9`、`8-18`、`*/2`   |
| 3    | 日期 | `1`、`1-7`、`*/2`    |
| 4    | 月份 | `1`、`1,4,7,10`、`*` |
| 5    | 星期 | `1-5`、`1`、`*`      |

`*` 表示任意值，`,` 表示列表，`-` 表示范围，`/` 表示步长。星期 `1` 是周一，因此 `1-5` 表示周一至周五。不支持秒字段。

| 目的            | Cron 表达式    |
| --------------- | -------------- |
| 每天 09:00      | `0 9 * * *`    |
| 工作日 09:30    | `30 9 * * 1-5` |
| 每 15 分钟      | `*/15 * * * *` |
| 每月 1 日 18:00 | `0 18 1 * *`   |

表达式按任务设置的 IANA 时区（如 `Asia/Shanghai`、`America/New_York`）解释，而不是查看运行记录时设备所在的时区。编辑器会校验表达式与时区，并预览接下来的三次触发；夏令时切换前后尤其应检查预览。

## App 与工作流的差异

App 定时任务会运行已保存的 App，适合独立的代码任务，例如周期性采集数据或清理数据。

工作流定时任务会保存配置好的输入，并在每次运行时使用它们。本地工作流任务在触发时解析该工作流最新保存的版本。团队模式下需选择已发布版本；任务会固定该版本，之后的编辑不会改变已调度的行为。

定时工作流必须能在无人参与时完成。包含 **Human Review** 或 **Ask User Question** 节点的工作流无法保存为定时任务；创建任务前必须移除这些节点，仅让定时路径避开它们并不足够。若原本有效的本地工作流之后被删除或变得无效，Workrun 会暂停其任务并记录错误，避免持续尝试运行。

## 运行时行为

- 保存、编辑、暂停、恢复或删除任务后，调度器会立即唤醒并应用变更。
- 到期的运行会写入正常的运行历史；可在运行面板和追踪中检查输出或错误。
- Workrun 会阻止同一 App 或工作流重叠执行。目标已排队、运行中或等待输入时，本次会标为跳过，并推进到下一个匹配时间。
- Workrun 启动时，关闭期间错过的周期性触发会推进到下一次未来触发，不会集中补跑积压任务。一次性任务错过执行时间也不会补跑。

对于会写入、发送或产生其他外部副作用的任务，请让 App 或工作流可以安全地重复执行，并把频率设得长于常见执行时长。启用前请先手动测试，并检查目标的权限。
