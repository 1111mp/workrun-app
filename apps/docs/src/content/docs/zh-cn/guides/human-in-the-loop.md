当自动化失误的代价高于询问一个人的代价时，请使用人工检查点。例如：批准对外回复、选择生产环境、处理敏感分类，或允许一次影响重大的工具调用。

Workrun 有三种不同的人工控制方式。应按决定类型选择，而不是把每次暂停都当作审核。

| 需要什么决定                 | 使用             | 如何继续运行                     |
| ---------------------------- | ---------------- | -------------------------------- |
| 需要批准、拒绝或修改一份草稿 | **人工审核**     | 批准或拒绝；批准时可编辑文本草稿 |
| 需要由人选择下一条路径       | **询问用户问题** | 选择一个选项                     |
| Agent 需要执行一次工具调用   | 工具确认         | 批准或拒绝该次工具调用           |

> **新版交互方式：** 工具授权、Questions 和 Human Review 现在直接显示在运行输出的节点消息中，不再通过全局弹窗逐项处理。可以先查看已有输出，稍后再提交决定；下方截图展示当前界面。

## 添加检查点前先确定范围

先确定审核人要看到什么，以及每种结果会如何继续。Human Review 节点引用的值必须在运行到该节点时存在于工作流 State 中。审核内容应保持精简：将待决定的内容作为主内容，仅把判断所需的事实作为上下文。

本指南假设一个 Agent 产出面向客户的回复 `reply_draft`，并附带 `customer_tier`、`case_priority` 与 `order_status` 三个参考字段。

```text
开始 → 生成回复草稿 → 人工审核 → 发送已批准的回复 → 结束
                            └──→ 记录拒绝结果 → 结束
```

`reply_draft` 和参考字段必须可供审核节点读取。如果上游节点将它们作为私有输出产生，请先将必要值发布到全局 State，或向审核节点授予相应的 State 访问权限。可参阅[工作流与 State](/zh-cn/concepts/workflows-and-state/)了解可见性模型。

## 配置 Human Review

1. 从节点面板拖入 **人工审核**，并将上游生成节点连接到它。
2. 选中该节点。在右侧 **审核请求** 中填写标题和说明，明确审核人需要决定的事项。
3. 将 **内容键** 设为 `reply_draft`，它会作为审核卡片的主要内容展示。
4. 将 **上下文键** 设为 `customer_tier, case_priority, order_status`。上下文会在草稿下方以只读 JSON 显示。
5. 只有当内容键是可安全修改的文本时才开启 **允许编辑**。审核人批准时的编辑只会写回这一个内容键，不能任意修改工作流 State。
6. 将 **批准** 连接至“发送已批准的回复”，将 **拒绝** 连接至“记录拒绝结果”，然后保存工作流。

| 字段     | 示例                                                             | 用途                             |
| -------- | ---------------------------------------------------------------- | -------------------------------- |
| 标题     | `批准客户回复`                                                   | 在待处理卡片中标识这项决定       |
| 说明     | `检查回复是否准确、语气是否得体，以及是否做出了无法兑现的承诺。` | 提供审核人应承担的判断标准       |
| 内容键   | `reply_draft`                                                    | 待审核的值；仅当为文本时才能编辑 |
| 上下文键 | `customer_tier, case_priority, order_status`                     | 判断所需的只读事实               |
| 允许编辑 | 开启                                                             | 让审核后的内容替换 `reply_draft` |

> **两个结果都要连接。** 如果“批准”或“拒绝”输出未连接，对应结果会停止这次运行。拒绝默认不是错误路径；应将其设计为明确的后续动作，例如记录原因、通知负责人，或安全结束。

## 运行、审核与恢复

用一个小型测试用例运行工作流。运行到检查点后，状态会变为 **等待输入**，Workrun 会在对应节点的输出中展示可交互的审核卡片。

审核人会看到配置的标题、说明、内容值和上下文。内容值为文本且已开启编辑时，草稿可被直接修改。点击 **批准并继续** 会保存决定及修改，并沿“批准”输出继续；点击 **拒绝** 则沿“拒绝”输出继续。

例如，[首页的天气与行程规划演示](/zh-cn/#一个日常例子查天气再规划行程)将审核节点的**内容键**设为 `input`，并开启**允许编辑**。用户最初输入“根据杭州天气给出行程规划”，在审核卡片中将“杭州”改成“上海”后批准。修改会写回 `input`，后续天气工具的 `city` 参数变为“上海”，行程规划也使用修改后的需求。

运行会从持久化检查点恢复：已经完成的上游节点不会再次执行。可在运行面板验证：此前节点应保留已完成结果，且只有被选择的下游分支会执行。

这些卡片不会弹窗阻塞整个应用。你可以先展开已完成节点的输出、查看工具结果或文件，再回来处理；也可以离开当前页面，稍后从**运行中心**打开对应运行。不同运行的请求可以分别处理，无需按全局弹窗顺序逐项操作。

提交成功后，卡片保留决定记录并变为只读，运行继续同一个任务。查看卡片本身不会占用请求；如果另一窗口已提交，刷新后查看已保存的结果。

## 需要人选路径时使用 Ask User Question

需要人做选择，而不是审核内容时，使用 **询问用户问题**。例如发布计划准备完成后，可以询问“要部署到哪里？”，并提供 **预发布环境** 与 **生产环境** 两个选项。

1. 添加 **询问用户问题**，并连接上游节点。
2. 设置要展示的问题和可选说明。
3. 添加用户可选择的选项；为每个选项写清晰标签，必要时补充其后果说明。
4. 将每个选项的输出手柄连接到对应分支，然后保存。

```text
准备发布 → 询问用户问题
                 ├── 预发布环境 → 部署到预发布环境 → 结束
                 └── 生产环境   → 人工审核 → 部署到生产环境 → 结束
```

每个选项都有内部标识，即使之后改动其显示标签也会保持稳定，因此已有分支连接不会失效。恢复前系统会验证所选选项，任意输入无法将运行导向其他分支。

## 工具确认比审核更窄

当每次调用都需要同意时，请在 Agent 的工具设置中开启人工确认，例如发送邮件、创建工单或修改记录前。工具确认卡片会展示请求调用的工具及输入；批准会执行这次调用，拒绝会将结果反馈给 Agent。它不会在画布上创建“批准/拒绝”分支。若生成内容和实际副作用都需要独立审查，可以同时使用工具确认和人工审核。

## 退出应用后继续处理

等待问题回答、人工审核或工具确认的运行，在重启后仍保留待处理请求。从**运行中心**打开原运行，检查已有输出，再在对应卡片提交决定。退出应用期间不会继续执行后续节点。

恢复前系统会检查原请求、已保存的工作流和检查点。检查点缺失或依赖不可用时，卡片会说明原因；解决问题后可以重新检查。已失效的请求只保留记录，不能再次提交。提交后若检查点应用失败，原决定仍会保留，运行显示为**已中断 · 待恢复**，可以从输出面板尝试恢复。

执行途中因退出或崩溃而中断的任务，也会保留在运行中心。恢复会检查检查点和操作结果，不会默认重新运行。失败或已停止的任务则需要修复后创建新运行。详见[运行、调试与追踪](/zh-cn/quality/runs-and-traces/)。

## 验证与排查

| 现象                 | 优先检查                                                                                                        |
| -------------------- | --------------------------------------------------------------------------------------------------------------- |
| 审核内容或上下文为空 | 确认所填 State 键在审核节点开始时存在，且该节点有读取权限。检查拼写与大小写。                                   |
| 草稿无法编辑         | **允许编辑**必须开启，**内容键**必须已设置，并且值必须是文本。对象和数组只能只读显示。                          |
| 提交决定后运行停止   | 连接对应的输出手柄。未连接的“批准”“拒绝”或问题选项输出都会结束该路径。                                          |
| 问题选择后走错分支   | 检查每条画布连接是否从预期选项的输出手柄发出，而不是仅从节点主体发出。                                          |
| 已完成步骤又被执行   | 应通过待审批项的“批准”“拒绝”或选择操作恢复；启动新运行或重放运行不同于从检查点恢复。                            |
| 审核人看到了敏感值   | 从**上下文键**中移除该字段、收紧 State 访问权限，然后使用测试数据重新运行。审核卡片只应显示做决定所必需的信息。 |

如需查看结合分支与人工审核的完整工作流，请参阅[构建第一个工作流](/zh-cn/guides/build-a-workflow/)。有关 State 发布、访问与持久化，请参阅[工作流与 State](/zh-cn/concepts/workflows-and-state/)。
