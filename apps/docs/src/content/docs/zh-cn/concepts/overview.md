---
title: Workrun 的工作方式
description: 理解 Workrun 如何把 AI 推理、代码和工具组织成可交付的自动化。
---

Workrun 解决的不是「如何多问一次模型」，而是「如何把一次有效的 AI 协作沉淀为可重复运行的能力」。

```text
用户输入 + 工作流状态
        ↓
Agent 推理 / Python 代码 / 外部工具 / 人工判断
        ↓
结构化结果、运行记录、评估结果与已发布版本
```

工作流负责安排步骤和状态流转；App 负责确定性代码与系统集成；Agent 处理需要推理的任务；MCP 和 Tool App 为 Agent 提供行动能力。

### 与单次对话的区别

- 工作流可以包含条件、分支、子工作流、终止和人工审核；
- 运行过程记录节点状态、工具调用、日志和轨迹；
- 失败或暂停后可以从检查点恢复，而非重跑全部步骤；
- 评估集和质量门让团队能够验证变更后再发布。
