# Human Review 附件展示与验收

## 展示规则

审批窗口会自动发现审核内容 `contentKey` 与额外上下文 `contextKeys` 中的资源引用，递归展示并按资源 ID 和版本去重。也可以在“附件 State 路径”中每行填写一个单独的文件字段、文件数组或包含文件引用的对象路径。

路径来自此审核节点可读取的平铺 State，例如 `processedPdf`、`report`、`artifacts` 或 `outputs.files.0`，不填写 `nodes.<节点ID>...`。上游私有输出必须授予审核节点读取权限。被 sensitive 策略隐藏的引用不会自动出现；显式选择不存在、不可读或不包含文件的路径会报错，避免遗漏待审附件后继续审批。

附件操作复用现有资源功能：

- 图片、视频：在审批窗口上方打开预览，关闭后返回原审批。
- PDF：打开系统 PDF 应用中的校验副本，查看器修改不会改变待审快照。
- 所有文件：选择保存位置并下载，包括文本、JSON 等没有媒体预览的文件。

附件仅供查看和下载，不允许在审批窗口上传、删除或替换。原有文本编辑、批准、拒绝和路由规则继续生效。资源二进制内容不会自动经过文本脱敏。

## Process → Human Review 配置

1. 使用 [PDF Process 示例](../../packages/python-sdk/examples/pdf-process/README.md) 配置文件处理节点。
2. 将图连接为 `Start → Process → Human Review`，审核的 Approved 与 Rejected 输出均可连接到 End，或分别连接后续节点。
3. 在 Process 节点的 State 读取权限中加入 Human Review 节点。
4. 在 Human Review 中配置：
   - 标题：`审核 PDF 处理结果`。
   - 描述：`检查生成的 PDF 和提取文本，确认后继续。`。
   - 额外上下文：`pageCount, textPageCount, warnings`。
   - 附件 State 路径：两行，分别为 `processedPdf`、`report`。
   - 允许编辑：关闭。
5. 上传 PDF 并运行。在全局审批窗口中打开 PDF，下载提取文本；批准后应走 Approved，拒绝后应走 Rejected。

CodeAct 生成的文件也可以审核：授权审核节点读取其 State，在附件路径填写 `artifacts`。如果文件已经包含在审核内容或额外上下文中，无需重复填写路径。

## 桌面验收

1. 分别用图片、视频、PDF 验证预览或打开，再下载验证内容。
2. 打开图片预览后，验证鼠标、缩放、Tab 和 Escape；关闭预览应返回审批，不能自动批准或拒绝。
3. 同一文件同时出现在内容、上下文和附件路径中时，应仅列出一次。
4. 保留待审批动作后重启应用，确认重新打开的审批仍显示原附件，并能下载。旧版本仅保存内容和上下文的审批请求也能发现其文件引用。
5. 移动原始上传文件，确认审批依然使用不可变快照。若快照丢失或损坏，预览/下载应显示错误，动作仍可保留或拒绝。
6. 移除上游授予审核节点的读取权限，显式附件路径应报错；不能通过填写完整命名空间路径绕过权限。

## 自动验证范围

后端测试覆盖附件选择、去重、嵌套路径、不可读及 sensitive 字段、实际图暂停与批准恢复、原件删除后快照仍可读取、待审批动作保留引用。前端测试覆盖持久化 payload 与旧版请求的附件发现，并排除路由元数据等无关字段。

真实桌面媒体预览、系统 PDF 打开、下载对话框以及应用重启仍需按上述步骤验收。
