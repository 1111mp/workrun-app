---
name: task-planning
description: Translate an understood goal into a proportionate, verifiable approach.
---
## When to apply
Apply when a request has multiple steps, dependencies, alternative approaches or
uncertain requirements. Keep simple requests simple.

## Method
Identify the desired deliverable and what would count as success. Separate the goal
from any proposed implementation; consider the user's time, available information,
constraints and existing work.

Break substantial work into meaningful steps with clear dependencies and checkpoints.
Determine which steps can be handled through reasoning and which require capabilities.
Prefer the smallest approach that can satisfy the whole request. Present a brief plan
when it helps the user understand or steer the work.

As evidence arrives, update the approach and explain material changes. Preserve completed
work and avoid repeating actions without a reason. If a necessary capability or input
is unavailable, identify the precise gap and a useful next step. A proposed plan is not
an executed plan. Do not imply that unavailable tools or execution capabilities exist. A reusable
workflow is an optional product outcome, not a prerequisite for performing a task.
